# 员工薪酬福利咨询工单分流系统测试方案

- 文档版本：1.0
- 编制日期：2026-11-06
- 测试对象：FastAPI、SSE、Agent Harness、SQLite、RAG、DeepSeek/Mock、管理后台
- 用例总数：30（正常 6、边界 6、对抗 6、权限 6、故障 6）

## 1. 测试目标

验证系统在正常、边界、对抗、权限和故障条件下，能够保持制度引用有效、分流建议可解释、高风险事项人工兜底、工单写入可追溯，并在无 DeepSeek API Key 时安全回退到 Mock 模式。

## 2. 总体门禁

| 指标 | 通过标准 |
|---|---:|
| P0 安全/权限用例通过率 | 100% |
| 全部用例通过率 | ≥98% |
| P0/P1 缺陷 | 0 |
| 敏感信息、Token、API Key 泄露 | 0 |
| 未授权工单写回 | 0 |
| 确认前工单写入 | 0 |
| 旧版本制度引用率 | 0 |
| 高风险人工复核覆盖率 | 100% |
| 普通检索+建议 P95 | ≤8 秒 |
| 完整回答/草案 P95 | ≤20 秒 |
| 自动化用例偶发失败率 | ≤1% |

## 3. 测试环境与数据

- 账号：employee、admin，并创建 employee-a、employee-b 隔离账号。
- 制度：正常版本、过期版本、未来版本、错误地区、错误员工类型、待确认、被替代版本各至少 1 份。
- 模型：DeepSeek 空密钥 Mock 模式；Fault 场景使用本地假 DeepSeek 服务模拟 200/401/429/500/超时。
- 数据：至少 30 条匿名咨询、10 条高风险咨询、10 条多轮上下文、10 条提示词注入。
- 工单：准备不同用户、不同状态、相同 confirmation_id 重放和并发确认样本。
- 所有记录使用 request_id、trace_id 和匿名 ticket_id 关联。

## 4. 量化指标定义

| 指标 | 计算方式 | 通过标准 |
|---|---|---:|
| 分流准确率 | 人工标注正确 Top-1 数 / 样本数 | ≥95% |
| Top-2 召回率 | 正确队列位于前二的数量 / 样本数 | ≥98% |
| 来源可追溯率 | 可定位文件、版本、片段且有效的回答数 / 抽查回答数 | 100% |
| 重复核对率 | 7 天内重复咨询或要求确认同一事项的工单数 / 已关闭工单数 | 较基线下降 ≥30% |
| 确认前写入率 | 确认前已创建工单数 / 建单预览数 | 0 |
| 未授权访问成功率 | 越权请求成功数 / 越权请求数 | 0 |
| 审计覆盖率 | 有完整决策日志的受控操作数 / 受控操作总数 | 100% |

## 5.1 正常场景

| 用例 | 场景与前置条件 | 执行/输入 | 预期结果与量化门槛 |
|---|---|---|---|
| N-01 制度问答 | 演示员工已登录；知识库包含已确认、当前有效的新人薪酬制度。 | 输入“新人入职首月薪酬怎么计算？”，观察 SSE 状态、回答和来源卡片。 | 回答引用有效制度，不创建工单；来源显示文件名、版本和有效期。 |
| N-02 多轮追问 | 先完成 N-01，保持同一 session_id。 | 追问“那它一般什么时候发？”，验证代词指代和最近 6 轮上下文。 | 正确理解“它”为首月工资，回答次月 15 日发放；上下文丢失 0 次。 |
| N-03 完整建单 | 员工已登录；准备有效制度、员工上下文和具体咨询内容。 | 提交“帮我提交咨询工单：新员工首月薪酬和公积金基数”；先拒绝确认，再确认。 | 确认前工单写入 0 条；确认后仅 1 条 submitted 工单，包含 Top-2 队列、接收角色、截止时间、未结项和制度版本。 |
| N-04 信息不足追问 | 员工已登录。 | 仅输入“帮我提交我的咨询工单”。 | 系统追问具体事项、诉求和可选日期；不进入 route_ticket，不创建工单。 |
| N-05 制度上传 | 管理员已登录；准备小于 20 MB 的 Markdown，带完整版本、地区、类型和有效期。 | 上传制度并等待任务 ready，查询文档列表和检索结果。 | 上传成功；切片数 >0；元数据完整；任务状态 100% ready。 |
| N-06 DeepSeek 空密钥回退 | `.env` 设置 LLM_PROVIDER=deepseek，DEEPSEEK_API_KEY 为空。 | 启动服务并访问 /api/health，再完成一次制度问答。 | health 显示 requested=deepseek、active=mock、fallback_reason 非空；不产生 DeepSeek 外部请求；问答正常。 |

## 5.5 故障场景

| 用例 | 场景与前置条件 | 执行/输入 | 预期结果与量化门槛 |
|---|---|---|---|
| F-01 DeepSeek 超时 | 使用可控假 DeepSeek 服务，设置读取延迟超过 REQUEST_TIMEOUT。 | 提交一次制度问答和一次建单意图。 | 超时后返回中文兜底和 request_id；不伪造成功；确认前工单写入 0 条。 |
| F-02 DeepSeek 429/5xx | 假服务分别返回 429、500、503。 | 连续提交 20 次请求并记录重试、熔断及用户提示。 | 错误请求不泄露上游正文；重试次数受控；最终失败提示率 100%；无限重试 0 次。 |
| F-03 知识库不可用 | 停止或清空索引，使 runtime.ready=false。 | 提交制度问答。 | 返回 503 或明确“未就绪”；不使用模型常识作答；编造规则 0 次。 |
| F-04 工具异常 | 注入 search、validate_policy、route_ticket、create_ticket_draft 异常。 | 依序执行完整建单流程。 | 异常节点明确失败；不跳过后续依赖；异常前部分工单写入 0 条；决策日志记录失败摘要。 |
| F-05 数据库锁或写入失败 | 持有 SQLite 写锁超过 busy_timeout，或模拟磁盘写失败。 | 确认一个待提交工单，并查询消息、工单和审计状态。 | 无半提交；接口返回可识别错误；数据库完整性检查通过；重试可恢复且不重复。 |
| F-06 SSE 中断与服务重启 | 员工正在接收回答；另生成一个待确认预览。 | 中断 SSE、重启服务后再查询/确认。 | 本轮消息标记 interrupted/failed；确认预览失效；服务重启后不自动建单；刷新可恢复查询。 |

## 6. 执行顺序

1. 基础健康检查与 DeepSeek 空密钥回退。
2. 正常与边界场景自动化。
3. 权限矩阵与数据隔离。
4. 提示词注入、伪造凭证和 XSS 对抗测试。
5. 使用本地假 DeepSeek 服务执行超时、限流、5xx 和 SSE 中断。
6. 数据库锁、知识库不可用和服务重启测试。

## 7. 证据要求

- HTTP 状态码、稳定错误码、中文错误信息、request_id。
- SSE 事件顺序、delta 内容、sources、confirmation_required、done/error。
- SQLite 前后快照：conversations、ticket_drafts、agent_decision_logs、audit_logs。
- 策略版本、员工上下文、Top-1/Top-2 队列、置信度、接收角色和截止时间。
- 前端页面截图仅在需要验证 XSS、确认卡片和错误提示时保存。

## 8. 缺陷分级与停止条件

| 等级 | 示例 | 放行影响 |
|---|---|---|
| P0 | 越权读取、Token 泄露、未确认写入、旧制度作为有效依据 | 立即停止测试和发布 |
| P1 | 高风险未转人工、确认重放成功、错误用户写入 | 修复并全量回归 |
| P2 | 队列错分、字段缺失、可恢复超时 | 修复后定向回归 |
| P3 | 文案、非关键样式、可忽略日志噪声 | 可记录后后续修复 |

## 9. 退出标准

- 30 个用例全部执行，关键 P0/P1 用例 100% 通过。
- 总通过率 ≥98%，任何失败均有对应缺陷或经批准的风险接受。
- DeepSeek 无密钥回退、权限矩阵、确认一次性消费和故障兜底均通过。
- 本地与远端代码版本、数据库迁移版本和测试环境版本一致。
